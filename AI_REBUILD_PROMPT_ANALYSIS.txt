========================================
一、專案定位
========================================

這是一個以 Python 為主的 Veo 3.1 本機影片生成工具，核心是桌面視窗應用程式，並附帶：
- FastAPI HTTP API / 靜態頁
- Discord Bot 互動式斜線指令
- SQLite 對話與命令歷史
- CSV / JSON 使用紀錄
- 可設定主 API 與備援 API
- 支援多種 Veo 影片生成模式

主要使用情境
- 使用者在桌面程式中輸入提示詞與素材，選擇片長 / 比例 / 畫質 / 生成類型後生成影片
- 使用者在 Discord 內使用 `/veo3` 指令進入互動流程
- 所有生成都會留下歷史與使用紀錄，可重新載入並再生成

========================================
六、Discord Bot 需求
========================================

指令
- 只保留 `/veo3`

整體流程
1. 使用者輸入 `/veo3`
2. Bot 顯示設定卡片
3. 使用者選擇片長 / 比例 / 畫質 / 生成類型
4. Bot 在頻道發送提示訊息
5. 使用者直接在頻道輸入提示詞，並依類型附加圖片或影片
6. Bot 用 wait_for(message) 擷取使用者那則訊息
7. Bot 顯示確認卡片
8. 使用者按下開始生成
9. Bot 顯示動畫進度
10. Bot 成功後回傳影片與花費資訊
11. Bot 失敗時顯示錯誤與重試按鈕

Discord UI 要求
- 介面文字使用繁體中文
- 可以加入適量 emoji
- 每個主要階段要有返回或取消能力
- 生成完成要顯示：
  - 片長
  - 比例
  - 畫質
  - 類型
  - 預估 Token
  - 預估 USD / NTD
  - 實際耗時
  - Discord 使用者 / 伺服器 / 頻道資訊

Discord 權限 / 限制
- 需要開啟 Message Content Intent
- Bot 透過頻道訊息讀取提示詞文字
- 若使用 guild sync，可讓斜線指令立即生效
- 若 global sync，Discord 指令可能要等待最長約 1 小時傳播

Discord 同步需求
- 支援多個 guild id，以逗號分隔
- 啟動時可同步到多個 guild
- 需避免重複指令
- 若採 guild sync，需要處理舊 global command 清除問題

七、影片生成類型
========================================

目前需要支援 7 種生成類型
- text_to_video
- image_to_video
- ref_subject
- ref_style
- video_extend
- inpaint_insert
- inpaint_remove

各類型概念
- text_to_video
  - 只有文字提示詞
- image_to_video
  - 至少 1 張圖片作為起始參考
- ref_subject
  - 1 至 3 張圖片作為主體參考
- ref_style
  - 1 至 3 張圖片作為風格參考
- video_extend
  - 以影片延伸方式生成
- inpaint_insert
  - 影片 + 遮罩，將內容插入指定區域
- inpaint_remove
  - 影片 + 遮罩，移除指定區域內容

八、目前專案的 Veo / Gemini 規則與限制
========================================

請優先遵守目前專案已編碼的規則，尤其在 Discord Bot 端必須防呆。

Gemini / Google 端目前已知規則
- durationSeconds 合法值以目前專案控制為主
- 1080p 以上需特別注意片長限制
- video_extend 有更嚴格限制
- 有些官方文件與實測行為不完全一致，因此需要同時保留：
  - 官方規格說明
  - 專案內已驗證的 workaround

目前專案內已反映的重要規則
- 1080p 與 2K 在 Bot 內只允許較高片長組合
- Bot 已移除 4K 選項，因為很容易超過 Discord 檔案上傳限制
- video_extend 需特殊處理
- ref_subject / ref_style 需特殊處理
- Bot 端必須對 duration / quality / gen_type 組合做自動修正

重建時應保留下列設計原則
- 不要把不合法的組合真的送去 API
- 在 UI 就先修正並提示使用者
- 若 API 回傳明確規格錯誤，要把錯誤原文顯示出來

十三、已知踩坑點與重建時必須避開的問題
========================================

1. Google API inlineData 問題
- 某些模型會回報 inlineData 不支援
- 需有 fallback 邏輯
- 錯誤字串比對要寬鬆，不能只比對完全相同句子

2. Discord 未受回應
- 若 slash command handler 內發生例外而未妥善回應，Discord 會顯示「該申請未受回應」
- 必須加全域錯誤處理與指令內 try/except

3. Discord Message Content Intent
- 若未在 Developer Portal 開啟，Bot 即使程式碼正確也可能無法正常讀取訊息內容

4. 全域指令與 guild 指令重複
- 切換同步策略時可能出現兩個同名指令
- 需明確設計同步與清理流程

5. 使用者素材輸入流程
- Discord Modal 不能直接上傳檔案
- 因此目前採用「Bot 發頻道提示 -> 使用者在頻道直接送文字與附件 -> Bot wait_for 擷取」流程

6. API 已完成但沒有影片 URI
- 某些情況 Google operation done=true，但 response 結構與預期不同
- 需保留 debug 日誌
- 需解析多種可能路徑
- 若仍沒有 URI，應把完整回應輸出到終端以便排查

7. 配額 / 帳單問題
- 常見錯誤：
  - RESOURCE_EXHAUSTED
  - exceeded spending cap
- 必須把 API 原始錯誤資訊完整顯示給使用者

8. README 與實作不一致
- README 舊內容提到 /veo
- 但目前實作已是 /veo3
- 重建時應以 /veo3 為準

1. 桌面視窗應用程式（主要使用方式）
2. FastAPI API 與簡單靜態頁
3. Discord Bot `/veo3` 互動式生成流程

請依照以下規格實作：

- 使用 Tkinter 建立主視窗
- 左側為對話列表

  - local_saved_path
- 要有成本估算函數 estimate_cost
- 若 Google API 回報 inlineData 不支援，需有 fallback 邏輯
- 若 operation done=true 但沒有影片 URI，要保留 debug 訊息並顯示可排查錯誤

五、生成類型
- 支援以下 7 種：
  - text_to_video
  - image_to_video
  - ref_subject
  - ref_style
  - video_extend
  - inpaint_insert
  - inpaint_remove

六、Discord Bot
- 使用 discord.py
- 指令名稱固定為 `/veo3`
- 使用者輸入 `/veo3` 後，不要直接要求在 slash command 參數中上傳素材
- 正確流程為：
  1. Bot 顯示設定選單
  2. 使用者選擇片長、比例、畫質、生成類型
  3. Bot 在頻道發送提示訊息

- 需有全域錯誤處理，避免 Discord 顯示「該申請未受回應」
- 需支援 guild sync 與 global sync
- discord_sync_guild_ids 需支援多個伺服器 ID，以逗號分隔

- Bot 必須依賴 Message Content Intent，程式內也要設 intents.message_content = True
